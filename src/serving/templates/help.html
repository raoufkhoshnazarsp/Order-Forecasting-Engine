راهنما و مستندات

این بخش دو چیز دارد: توضیح اینکه هر عدد از کجا می‌آید، و مستندات فنی API برای کسانی که می‌خواهند نتیجه را در سیستم خودشان استفاده کنند.

قالب دادهٔ ورودی

فایل اکسل باید در یکی از این سه چیدمان باشد؛ موتور هر برگه را خودش تشخیص می‌دهد:

  1. مدل دادهٔ تجاری — ردیف = تاریخ × ورتیکال × دسته (و اختیاری روش پرداخت) با ستون‌های سفارش و GMV. (پیشنهادی)
  2. دادهٔ روزانهٔ تجمیع‌شده — ردیف = تاریخ × موجودیت.
  3. سفارش‌های خام — هر ردیف یک سفارش؛ موتور خودش جمع می‌زند.
دانلود قالب خالی دانلود دادهٔ نمونه

«قالب» را وقتی استفاده کنید که ساختار فایل خودتان را می‌سازید؛ «نمونه» را برای آزمودن جریان با دادهٔ ساختگی ۲۰۰ روزه.

هر عدد یعنی چه؟

  • WAPE — جمع قدرمطلق خطا ÷ جمع واقعی. کمتر بهتر است.
  • Bias — جهت خطا. مثبت یعنی پیش‌بینی معمولاً بالاتر از واقعیت.
  • پوشش بازهٔ ۹۰٪ — درصد دفعاتی که مقدار واقعی داخل بازه بوده است؛ باید نزدیک ۹۰٪ باشد.
  • سناریوی بدبینانه/واقع‌بینانه/خوش‌بینانه — از انحراف معیار خطای بک‌تست ساخته می‌شوند، نه از حدس.
  • سناریوی حساسیت — یک فرض قابل‌تنظیم روی پیش‌بینی پایه؛ پیش‌بینی اصلی دست‌نخورده می‌ماند.

مستندات API

همهٔ مسیرها JSON برمی‌گردانند مگر آن‌که صریحاً فایل باشد.

مسیرکار
POST /api/runsآپلود فایل، اجرای گیت کیفیت، ساخت نشست و پیش‌نمایش
POST /api/runs//forecastپیش‌بینی و بک‌تست با توکن تأیید
POST /api/runs//comparisonداشبورد ماهانه از همان فایل
POST /api/runs//sensitivityسناریوی حساسیت با فرض قابل‌تنظیم
GET /api/runs/بازیابی نشست
GET /api/runsسابقهٔ اجراها
GET /api/runs//packageدانلود فایل تحویل
POST /api/qualityفقط گزارش کیفیت (بدون نشست)، سازگار با نسخهٔ قبلی
POST /api/forecast · /api/delivery · /api/comparisonمسیرهای قبلی: آپلود مستقیم با توکن، سازگار با کلاینت‌های قدیمی
