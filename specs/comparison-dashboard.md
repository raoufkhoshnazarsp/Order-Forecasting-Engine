# مشخصات داشبورد مقایسه‌ای

> صفحهٔ `/comparison` — مقایسهٔ ماه‌های گذشته با سه سناریوی ماه آینده، به تفکیک ورتیکال و کل.
> مرتبط با تسک کانبان «داشبورد مقایسه‌ای ماهانه + سه سناریو» و فاز ۸ رودمپ.

## ۱. دامنه و قرارداد داده

| مورد | قرارداد |
| --- | --- |
| ورودی | همان فایل تحویل/داده‌سازی `date × vertical × category` |
| Grain خروجی | `month × vertical × scenario` |
| ماه‌ها | ۶ ماه کامل گذشته + ماه آیندهٔ میلادی (قابل تنظیم ۳–۱۲) |
| ورتیکال‌ها | ۷ ورتیکال دسته‌دار + `SNAPP-VENTURE` + `SNAPP-PAY` + `VERTICALS` |
| کل | `VERTICALS` = جمع دقیق ۷ ورتیکال (بدون Venture/Pay) |
| GMV | `order × AOV` در همان ماه و همان سناریو |
| AOV | نسبت، جمع‌پذیر نیست: `ΣGMV / Σorders` |

## ۲. ساخت سناریوها

سناریوها **دستی انتخاب نمی‌شوند**؛ از خطای بک‌تست rolling-origin ساخته می‌شوند:

```
σ_m      = انحراف معیار نسبی خطای پنجره‌های بک‌تست برای همان ورتیکال و افق
پایه     = پیش‌بینی نقطه‌ای مدل برنده
بدبینانه = پایه × (1 − z·σ_m)     z = 1.2816  (بازهٔ ۹۰٪)
واقع‌بینانه = پایه
خوش‌بینانه = پایه × (1 + z·σ_m)
```

قواعد:

- اگر پنجرهٔ بک‌تست کمتر از ۳ باشد، `σ_m` از باقی‌مانده‌های درون‌نمونه گرفته می‌شود و
  داشبورد برچسب «اعتبار کم» می‌گیرد.
- سناریوها هرگز روی `VERTICALS` جدا محاسبه نمی‌شوند؛ همیشه جمع سه سناریوی ۷ ورتیکال.
- مقدار منفی به صفر بریده می‌شود؛ `σ_m` سقف ۰٫۶ دارد تا سناریو غیرواقعی نشود.

## ۳. چیدمان صفحه

```
┌──────────────────────────────────────────────────────────┐
│ سایدبار: اجرا · مقایسه · گزارش                           │
├──────────────────────────────────────────────────────────┤
│ KPI: جمع ۶ ماه · ماه آینده (واقع‌بینانه) · رشد · اعتبار  │
├──────────────────────────────────────────────────────────┤
│ جدول ۱ — گذشته: ورتیکال × ۶ ماه (سفارش / GMV)            │
│          + ستون سهم و رشد                                │
├──────────────────────────────────────────────────────────┤
│ جدول ۲ — ماه آینده: ورتیکال × (بدبینانه | واقع‌بینانه |  │
│          خوش‌بینانه) برای سفارش، و همان برای GMV          │
├──────────────────────────────────────────────────────────┤
│ نمودار میله‌ای گروهی: ۶ ماه گذشته + ۳ سناریو              │
│ کلید شاخص: سفارش / GMV / AOV                             │
├──────────────────────────────────────────────────────────┤
│ کارت اعتبار: WAPE/Bias هر مدل، تعداد پنجره، پوشش بازه     │
└──────────────────────────────────────────────────────────┘
```

## ۴. اندپوینت‌ها

- `GET /comparison` — صفحهٔ HTML (سرور-رندر، همان تم تیره).
- `POST /api/comparison` — بدنه: `file`, `horizon`, `model`, `months`؛ پاسخ JSON با
  `months[past]`, `scenarios[next_month]`, `validity`.
- `GET /api/comparison/sample` — نمونهٔ آماده برای پیش‌نمایش بدون آپلود.

## ۵. تست‌های لازم (`tests/test_comparison.py`)

1. تعداد ماه‌های گذشته = پارامتر ورودی و همه کامل‌اند.
2. `VERTICALS` هر ماه = جمع ۷ ورتیکال همان ماه.
3. Venture و Pay در `VERTICALS` جمع نمی‌شوند.
4. `بدبینانه ≤ واقع‌بینانه ≤ خوش‌بینانه` برای هر ورتیکال و هر ماه.
5. `GMV = order × AOV` در هر سلول.
6. مجموع ماهانه با جمع روزهای همان ماه برابر است.
7. نبود پنجرهٔ کافی → برچسب «اعتبار کم» و نه خطا.
8. ماه آینده دقیقاً ماه میلادی بعد از آخرین ماه داده است.

## ۶. معیار پذیرش

جدول گذشته با جمع روزانهٔ فایل ورودی دقیقاً بخواند، سه سناریو از خروجی بک‌تست
قابل بازتولید باشند، و همهٔ تست‌های بخش ۵ سبز شوند.
